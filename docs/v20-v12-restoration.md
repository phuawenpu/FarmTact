# Restore V12 as the product baseline

The user's 18 September correction supersedes the V15–V19 requirement to funnel
all workflows through one sequential card shell. V12 source
`9fd57898b8a4e3b69a40c3abf03895f0fcb05daf` defines the interface baseline:
named Plan, Farm, Council research, Farm tools, Crops, Data, Outcomes and Setup
sections; a central board; visible Council roles; and the seven-stage farmer loop.

V20 is a restoration release. Its entrypoint selects the retained V12 FarmerWorkflow
explicitly, independent of publication number, rather than enabling V13's tactical
console or V15's integrated cards. The original V12 workflow, planning, board,
records, crop and research component sources remain intact. Historical edition
chooser/review links are removed because current-game deployment serves only `/`
and `/play`. Audio preferences continue to use the current release namespace.

Current backend services, validated gateway, durable admission limits, reviewed
imports, revision-bound proposals, task history and disabled real operations remain.
V20 starts a separate ordinary sandbox; no historical state is imported or overwritten.
Original source/images and retained data remain private and immutable.

Verification requires the original V12 lifecycle against the real backend, all
named sections at 360/390/430/desktop widths, the production build and generated
contracts, full isolated PostgreSQL regression, exact staged-image operator/browser
checks and shared-state preservation before publication. Browsing and local
calculation must not submit inference.

After this baseline is public, compare isolated original V12/V15/V19 applications.
Any later improvements must be small, observed fixes inside V12's structure and
receive a separate immutable publication. The later universal card-deck navigation,
three-action limit and buried named sections are not design requirements.

Staged compatibility finding: the V12 approval predicate could enable immediately
after the completed session poll but before the refreshed workflow response. That
window sent the old strategy identity and was rejected with 409. Restoration now
requires the server-owned proposal approval eligibility before enabling approval;
the current result and proposal bindings still apply. No approval checks are relaxed.
