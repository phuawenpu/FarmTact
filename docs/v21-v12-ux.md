# V21: small improvements to the restored V12 workspace

V20 restored the original V12 product structure before this follow-up. V21 keeps
Plan, Farm, Council research, Farm tools, Crops, Data, Outcomes and Setup, the
farm board, visible seven-role Council and explicit proposal/approval controls.
It does not reactivate the V15–V19 card shell. See the comparative walkthrough.

Published at `/` and `/play` from `b980180dbb49a5261e43ee1d8e4916cc24457d7f`.
See [final verification and limitations](../reports/v21/README.md).

## Changes

- The seven-stage rail scrolls and focuses actual sections. It cannot mark work
  complete; persisted milestones continue to report saved progress. Missing
  stages explain their prerequisites without mutation.
- Calculate precedes metrics and the board. First-visit guidance names this
  action and explains that Council advice is optional.
- Metrics, board and the complete dated schedule bind to one selected strategy.
  Preview selection is explicitly unsaved. The board shows one earliest cycle
  per bed, counts additional cycles and links the full schedule below.
- Recorded batches resolve crop identity through their recipe. Where no stage
  is supplied they say “recorded batch”; scheduled dates do not certify actual
  harvest readiness. Unknown calculated metrics remain Unknown.
- Planning dialogs contain keyboard focus, support Escape and return focus and
  scroll to their opener. Unsent proposal fields/questions survive dialog close
  only within the mounted workspace, isolated by revision/strategy/adviser;
  successful submission clears the relevant draft. Reload/navigation clears
  these local drafts, as disclosed in the interface.
- Crop evidence arriving after profile close cannot reopen the dialog; keyboard
  focus returns to the crop card.

## Staged timeout recovery finding

The initial V21 image passed the 62-check exact-image responsive suite. Repeated
lifecycle trials exposed an existing numerical-worker cleanup failure under host
load: a child still alive after bounded termination made `process.close()` raise,
masking the original timeout and skipping gate release. A narrow follow-up makes
cleanup exception-safe while preserving bounded deadlines and single-worker
admission. The interface also identifies failed calculations and points back to
the explicit retry action, retaining saved inputs. This backend correction passed
a fresh full regression and restaged image checks; the first image was not published.
The initial lifecycle harness additionally needed an unambiguous stage selector;
its initial failed assertion did not indicate failed approval.

The final slow-connection trial also exposed overlapping V12 status polls. The
restored workflow now permits one pending status read per job, ignores responses
from a disposed workflow and stops polling on terminal state. Reads reconcile the
same job and never resubmit a mutation. A delayed-response fixture verifies this
without inducing backend work. The delayed crop evidence harness now holds an
actual server profile response in one route instead of overlapping route handlers.
The backend correction passed the complete isolated regression: 811 passed, one
skipped; these final polling changes are frontend-only.

Operator verification also bounds its SSH transport to two remote interpreters;
this is separate from unchanged application admission and never retries a request.
