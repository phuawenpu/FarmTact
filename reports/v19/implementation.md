# V19 Council decision cards — candidate verification

V19 places Council review beside every calculated plan without creating another
navigation mode. Each plan card carries a server-bound Council identity and a
layered decision brief: dated allocations, affected beds, current review status
and a clear boundary between advice, planning and approval. The existing Council
card then shows the frozen result, revision, seven roles and recorded facts. It
can be submitted only through the existing explicit review gateway.

The V11–V13 crop, evidence, research, data and replay depth remains available
through the five-card tools index and contextual returns. Reading, comparison,
swiping and replay are provider-free; Council review is optional and farm work
continues to require its own reviewed approval path. Actual operations are disabled.

checks; the Council card browser test passed nine checks; the isolated PostgreSQL
regression passed 804 tests with one skip; and the complete local browser journey
passed at 360, 390, 430 and desktop widths with no automatic provider requests.
Private staging, operator acceptance, exact-image browser verification and shared
preservation remain release gates.
