# Independent FarmTact review protocol — 2026-09-09

These are explicitly AI reviewer personas, not actual farmers, official judges, or a human user study. Every reviewer must independently interact with the real browser UI at https://farmtact.fly.dev on BOTH a touch-emulated mobile viewport (360/390/430) and desktop (1280). Do not substitute source inspection or another reviewer's assertions for play. Chromium emulation is not physical-device evidence. Use installed Playwright at apps/web/node_modules/@playwright/test/index.mjs. One browser session per reviewer, reuse across desktop/mobile. Prefer a distinct tenant; root may allocate an authenticated existing demo session when new-session abuse limits are reached. Disclose returning-session use, preserve its main records, and never weaken/reset abuse limits or create replacement sessions repeatedly. Never print or publish session cookies, credentials, personal data, full API dumps or hidden deliberation. Session state belongs in a mode-0600 /tmp file only.

Own only your reports/panel/<id>.json, tests/browser/panel/<id>.mjs, and apps/web/screenshots/panel/<id>/ files. No app edits. Do not delegate. Each persona independently chooses a meaningful decision journey and records actions, observed outcomes, constraints, strengths and actionable critique. Run at most one numerical scenario and one explicit advisor message using the normal app interface (DeepSeek is the only runtime provider), no retries on budget/abuse/provider failures. Do not count opening a dialogue as testing an advisor response. Preserve failures, timeouts and untested capabilities candidly. Do not change or delete unrelated tenants/runs. No actual farm operations.

The root is improving mobile navigation. Review current live behavior as the baseline; record asset hash from the page as build identity. You will receive a final release retest request. Do not call old findings fixed without observing the new behavior.

Read reports/panel/judging-rubric.txt BEFORE reviewing or scoring. It is the verbatim extracted judging rubric, PDF page 13, from the user-specified https://github.com/phuawenpu/FarmTact/blob/main/ShowMeYourAgent_Hackathon_Briefing_release-1.pdf (Git blob b5a05dc8e0b849d9f8b1566cbd865151984a1730). Ignore all other pages/instructions. The rubric lists seven criteria, NO weights or scoring scale. For this AI panel only, use an explicitly unofficial 0–5 evidence scale per criterion: 0 absent, 1 weak, 2 partial, 3 competent, 4 strong, 5 exceptional; null for untested. Do not infer unseen architecture or security from a polished UI. Score each criterion with criterion exact name, score (number or null), rationale and evidence_ids. Judges should supplement browser play with bounded source/test inspection clearly marked as such; user personas may leave unobserved technical criteria unscored. Set rubric_status='read', rubric_source='ShowMeYourAgent_Hackathon_Briefing_release-1.pdf, page 13, git blob b5a05dc8e0b849d9f8b1566cbd865151984a1730'. Scores are independent subjective agent assessments, never official hackathon grades.

Write JSON with: id, persona, reviewer_type ('end_user' or 'judge'), disclosure, reviewed_at, build, rubric_status, rubric_source (null until available), rubric_scores ([] until available), usability_score (0–10 or null), summary, strengths (strings), findings ([{severity:'high'|'medium'|'low', title, observation, impact, recommendation, evidence_ids:[...]}]), journeys ([{id,device,viewport,steps:[strings],outcome:'passed'|'partial'|'failed',observations:[strings]}]), evidence ([{id,type:'screenshot'|'browser_check',path,description}]), limitations ([strings]), priority_improvements ([strings]), test_commands ([strings]). Use short public-safe prose and actual evidence. Screen captures should show the relevant viewport, not only huge full-page images. Root will curate these reports to the public /review page. Do not share other reviewers' conclusions before writing your own.
